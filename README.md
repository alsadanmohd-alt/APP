# قريب — MVP عربي لتأجير الأغراض

تطبيق Next.js وTypeScript وSupabase، عربي RTL ومتجاوب للجوال. العملة الافتراضية الريال السعودي. يختار المستخدم موقعه عبر «أماكن أخرى» (منطقة ثم مدينة/محافظة من مناطق المملكة) أو باستخدام GPS. الخريطة تستخدم Leaflet وOpenStreetMap.

## التشغيل السريع

تحتاج Node.js 20.9 أو أحدث وpnpm. داخل مجلد المشروع:

```sh
pnpm install
pnpm dev
```

افتح http://127.0.0.1:3000. بدون مفاتيح Supabase تظهر معاينة صريحة ببيانات توضيحية. لا تدّعي المعاينة تنفيذ تسجيل دخول أو حجز؛ يلزم الإعداد التالي لتفعيل الوظائف الفعلية. أيقونات الأغراض التوضيحية ليست صور منتجات حقيقية؛ تظهر صور المستخدمين في الإعلانات المنشورة.

## تفعيل الحسابات والبيانات والصور

1. أنشئ مشروعًا في Supabase.
2. نفّذ `supabase/schema.sql` مرة واحدة في SQL Editor **داخل مشروع جديد**. الملف ينشئ الجداول والسياسات ودوال الحجز وحاوية الصور؛ ليس ترحيلًا قابلًا للتكرار فوق قاعدة قائمة.
3. انسخ `.env.example` إلى `.env.local` واملأ:

```env
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=YOUR_PUBLIC_ANON_OR_PUBLISHABLE_KEY
```

4. استخدم المفتاح العام المخصص للمتصفح، ولا تضع `service_role` أو مفتاحًا سريًا في أي متغير `NEXT_PUBLIC_`.
5. في Authentication فعّل Phone واضبط مزود SMS ورمزًا بطول 6 أرقام. التسجيل والدخول بالجوال ورمز التحقق فقط. راجع UPDATE.md للتفعيل وترقية الحسابات القديمة.
6. أعد تشغيل خادم التطوير بعد تعديل المتغيرات.

لا توجد بيانات مستخدمين حقيقية أو كلمات مرور جاهزة في المشروع. المعاينة لا تُخلط مع بيانات Supabase؛ عند ربطه يبدأ المشروع بأغراضك الفعلية فقط.

## تجربة المسار الكامل

1. أنشئ حسابين مستقلين، وافتحهما في متصفحين أو جلسة خاصة.
2. من حساب المالك: أضف غرضًا وصورة أو أكثر، والسعر ورقم التواصل، واختر المنطقة ثم المدينة (والحي اختياري). استخدام الموقع الفعلي (GPS) لتدقيق نقطة الاستلام اختياري أيضًا؛ بدونه يُعتمد موقع المدينة المختارة.
3. من حساب المستأجر: حدد موقعًا قريبًا، وابحث وصفِّ النتائج بالمسافة والسعر والفئة، وجرّب القائمة والخريطة وتفاصيل الغرض.
4. من تفاصيل الغرض، اتصل مباشرة برقم المالك أو ابدأ محادثة داخل التطبيق لتنسيق المدة والسعر وموعد الاستلام. لا توجد تواريخ حجز أو تأمين ضمن التطبيق نفسه؛ الاتفاق يتم بين الطرفين مباشرة.
5. **لا توجد خطوة قبول أو رفض**: بمجرد ضغط المستأجر «بدء محادثة داخل التطبيق» تُفتح المحادثة فورًا، وتظهر له من تفاصيل الغرض المسافة الفعلية بينه وبين المالك (رقم بالكيلومتر فقط)؛ الإحداثيات الدقيقة نفسها لا تُرسل للمتصفح أبدًا لأي طرف. يستطيع الطرفان مراسلة بعضهما من بطاقة التواصل مباشرة. تُحدّث الرسائل كل أربع ثوانٍ أثناء فتح المحادثة؛ زر تحديث اللوحة يجلب تغيرات جديدة.
6. **لا توجد خطوة تأكيد إتمام**: يستطيع المستأجر كتابة تقييم واحد لأي محادثة بدأها في أي وقت، دون انتظار أي إجراء من المالك. لوحة المالك تعرض له أغراضه فقط («أغراضي»)؛ لا يوجد تبويب منفصل لعرض طلبات التواصل الواردة — التواصل والتنسيق يتم مباشرة بالهاتف أو المحادثة.
7. من تبويب «أغراضي»، يستطيع المالك **تعديل** أي غرض نشره (كل الحقول، مع الاحتفاظ بالصور الحالية إن لم يرفع غيرها) أو **حذفه نهائيًا** — الحذف يُزيل معه أي محادثات ورسائل وتقييمات مرتبطة به.

## قواعد البيانات والخصوصية

- `items`: بيانات عامة تشمل إحداثيات مقربة إلى منزلتين عشريتين، أي شبكة تقارب كيلومترًا. المسافة المعروضة تقديرية؛ الفلترة عند الحدود تقديرية أيضًا.
- `item_locations`: الموقع الدقيق في جدول مستقل، بلا أي سياسة قراءة إطلاقًا — لا يُرسل عبر الشبكة لأي طرف مهما كانت صلاحيته. القراءة فقط عبر دالتين (security definer تتجاوزان RLS بصلاحية مالك الجدول، وتتحققان من الصلاحية داخليًا): `get_pickup_distance` تُعيد لمستأجر بدأ محادثة (أو للمالك) رقم المسافة بالكيلومتر فقط، لا الإحداثيات؛ و`get_owner_item_location` تُعيد الإحداثيات الدقيقة لصاحب الغرض نفسه فقط، لغرض التعديل.
- `bookings`: خيط تواصل مفتوح بلا موافقة مسبقة ولا تواريخ ولا مبالغ ولا حالة (لا يوجد عمود حالة؛ لا توجد خطوة «تأكيد إتمام»)؛ يُنشأ تلقائيًا أول مرة يبدأ فيها المستأجر محادثة، ويقرأه طرفاه فقط. الإنشاء عبر دالة قاعدة بيانات فقط؛ المالك يُستخرج من الغرض ولا يُقبل من العميل. حذف الغرض يحذف معه محادثاته ورسائله وتقييماته (ON DELETE CASCADE).
- فهرس فريد يمنع المستأجر نفسه من فتح أكثر من محادثة واحدة لنفس الغرض (يعيد نفس المحادثة القائمة بدل إنشاء أخرى).
- `messages`: قراءة وإرسال لطرفي المحادثة فقط، في أي وقت.
- `reviews`: عامة، وكتابة التقييم متاحة لمستأجر بدأ محادثة فعلية حول الغرض، مرة واحدة لكل محادثة، دون انتظار أي تأكيد من المالك.
- تعديل الغرض عبر دالة `update_item` (لصاحبه فقط، تعيد تقريب الإحداثيات العامة تلقائيًا)؛ حذفه عبر سياسة RLS تسمح فقط لصاحبه.
- الصور عامة عمدًا حتى يراها المستكشفون. الرفع مقيد بمجلد المستخدم، وأنواع JPG/PNG/WebP، وحجم 5 ميجابايت للصورة. يعيد العميل ترميز الصور إلى WebP لإزالة EXIF/GPS، ويقلصها إلى 1600 بكسل. هذا لا يمنع مستخدمًا تقنيًا من رفع ملف مباشرة خارج الواجهة؛ قبل الإطلاق الواسع أضف معالجة صور موثوقة على الخادم إذا أردت ضمان إزالة البيانات الوصفية لكل رفع.
- اسم الحي والوصف والصور عامة؛ تُظهر الواجهة تنبيهًا بعدم تضمين عنوان المنزل أو الهاتف فيها. لا تُرسل إحداثيات المالك الدقيقة إلى الخريطة العامة. مزود الخريطة يتلقى طلبات البلاطات عند الاستكشاف، ومزود الخطوط يتلقى طلب الخط؛ يمكن استضافته محليًا لاحقًا.
- لا يوجد مفتاح إداري في التطبيق، ولا بيانات خاصة محفوظة كتجربة في localStorage. Supabase يدير جلسة تسجيل الدخول في المتصفح.

## التحقق

```sh
pnpm test
pnpm typecheck
pnpm build
pnpm start
```

اختبارات الحسابات الرياضية تعمل محليًا. اختبار `tests/security.test.mjs` يتخطى التشغيل تلقائيًا دون إعداد مشروع Supabase اختباري مستقل. لتنفيذه، طبّق المخطط في مشروع اختبار فارغ ثم اضبط متغيرات البيئة التالية **في جلسة الاختبار فقط**:

```text
TEST_SUPABASE_URL
TEST_SUPABASE_ANON_KEY
TEST_SUPABASE_SERVICE_ROLE_KEY
```

ثم شغّل `pnpm test`. ينشئ الاختبار ثلاثة مستخدمين مؤقتين ويتحقق من: منع قراءة الموقع الدقيق أو المسافة قبل بدء محادثة، وأن بدء المحادثة فوري وبلا موافقة، وخصوصية المحادثة، وأن كتابة التقييم مقيّدة بمستأجر بدأ محادثة فعلية، وأن التعديل والحذف مقيّدان بصاحب الغرض فقط مع حذف تتابعي للمحادثات والرسائل والتقييمات عند حذف الغرض. ينظف بياناته في النهاية. لا تشغله على قاعدة إنتاج. المفتاح الإداري مطلوب للاختبار فقط ولا يدخل التطبيق أو ملفات التسليم.

## النشر

المخرج المطلوب هنا مشروع قابل للتشغيل؛ لم يُنشر رابط عام ولم يُنشأ حساب Supabase نيابة عنك. انشر مشروع Next.js على مضيف يدعمه مثل Vercel، وأضف المتغيرين العامين وأعد البناء، ثم حدّث Site URL وإعدادات الجوال في Supabase. تحديد الموقع يحتاج HTTPS أو localhost. لا تستخدم `127.0.0.1` كرابط للمعلمين أو العملاء؛ هو معاينة على جهازك فقط.

## حدود النسخة الأولية

- السعر وطلب التواصل فعليان بعد الربط، لكن **لا توجد بوابة دفع أو تحصيل إلكتروني أو تأمين أو إدارة نزاعات**. المدة والسعر النهائي والدفع والتسليم كلها تُتفق عليها بين الطرفين مباشرة عبر الهاتف أو المحادثة الداخلية.
- لا تشمل النسخة تنبيهات دفعية، استعادة كلمة المرور، توثيق الهوية، إشراف المحتوى أو استرداد مبالغ؛ ليست ضمن النطاق المنفذ.
- البحث والفلترة في المتصفح بعد تحميل الأغراض، مناسب لحجم MVP صغير؛ قبل نمو الكتالوج انقل البحث إلى استعلام جغرافي مفهرس مع تقسيم النتائج إلى صفحات.
- قد تبقى صور يتيمة إذا نجح رفعها وفشل نشر الغرض؛ أضف تنظيفًا دوريًا قبل التشغيل الواسع.
- خريطة OpenStreetMap وخط Google يحتاجان اتصال إنترنت؛ تظل القائمة ومظهر الخط البديل قابلين للاستخدام عند تعذر تحميلهما. راجع سياسة مزود البلاطات قبل زيادة الحمل.
